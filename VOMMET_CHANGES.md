# Vommet changes compared with Commet

Everything this fork changes relative to upstream [Commet](https://github.com/commetchat/commet),
so the fork stays auditable and easy to rebase. **Rule: every change to Commet's code or
behaviour adds an entry here in the same commit.** Issue numbers refer to
[this repo's tracker](https://nether.codes/robocub/vommet/issues).

Status: **main** = merged; **testing** = on the [`testing`](https://nether.codes/robocub/vommet/src/branch/testing)
branch (in tester builds) and on its own branch, waiting for hands-on testing before it is merged.

## Identity and separation from Commet's infrastructure

| Change | Where | Status |

## Deliberately unchanged

- Matrix event types and account-data keys under `chat.commet.*` (calendars, photo albums, recent emoji, sidebar order…), so data stays compatible with Commet.
- The `commetchat://` URL scheme (widget deep links), Flutter MethodChannel names, and the Rust library name `rust_lib_commet`.
- Strings that credit or point to Commet on purpose (README credits, "donate to Commet" text in profile badges).

## GitHub copy

| Change | Status |
|---|---|
| GitHub copy (`github-copy.yml`): one-way force-push of main, testing and ci/windows* to github.com/dark-collective/vommet for Windows CI; replaces the Forgejo push mirror (its `+refs/*:refs/*` fetch refspec wrote GitHub's state back over ours) | main |
| GitHub copy pushes snapshots only (main, testing, ci/windows*, ci/xplat*), to a standalone (non-fork) repo: each branch is one orphan commit (tree = the Forgejo tip's tree, no parent, neutral message without '#'), so our issue numbers can't link to Commet's PRs; a guard refuses any other or issue-linking commit, and every other GitHub branch is pruned | testing (`chore/github-snapshot`) |

## CI speed

| Change | Status |
|---|---|
| Housekeeping workflows (`github-copy`, `upstream-sync`, `upstream-promote`, `nightly`) run on a separate 2-slot "light" Forgejo runner, so they never wait behind builds in the main runner's single slot (the GitHub builds start when github-copy finishes) | main |
| Heavy CI jobs (build, APK, Flatpak, integration) skip on a push when the exact commit, or the green testing containing it, already passed them (`.vommet/ci/already-passed.sh`); the Flatpak bundle also builds on sync/testing, so release files come from the candidate's runs | main |
| CI image `.vommet/ci/Dockerfile` (apt packages, Flutter, Rust, Android SDK, Tuwunel preinstalled; built on the runner, used locally): jobs no longer install toolchains on every run | main |

## Nightly runs

| Change | Status |
|---|---|
| `.forgejo/workflows/nightly.yml` on main starts the nightly integration workflows on testing via the API (Forgejo only fires `schedule:` on the default branch, so their own crons never ran) | main |
| Nightly runs at 06:55 UTC (was 03:41, which collided with sync cuts) and skips the full integration suite when testing's commit already passed it, except on Sundays (flake probe); synapse and secure-setup suites always run | main |
